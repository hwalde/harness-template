# Harness knowledge – index
Catalog of this skill's documents. One sentence per file on what it is about and which topics appear (as of: 2026-09-04). For building, restructuring, or extending a harness read all of them; for single questions the matching ones. The state of a *particular* harness is not here but in that project's `HARNESS.md` (built from `assets/project/HARNESS.md`): skill version, setup status, coding agents in use and what they support, sync duties, decisions with their reasons, deviations from the skill's templates, open points.

- [setup.md](setup.md) – Guided setup in eleven steps (0–10) after `scripts/build.py` placed the files: repository and remote, where the skill is installed for colleagues, language, project and repository layout (one repo vs. mother/child), coding agents and feature investigation, knowledge storage (wiki or alternatives), MCP/access, scripts, autonomous runs/monitoring/security, architecture and guidelines, subagents/evaluators, workflow, wrap-up with checklist.
- [fundamentals.md](fundamentals.md) – What a harness is (everything except the LLM), why all building blocks steer the context, checklist of a good harness, enablement and red lines, order as an architectural requirement.
- [rule-files.md](rule-files.md) – AGENTS.md/CLAUDE.md (`@AGENTS.md`), the four places, what belongs in and what does not (Pareto, pitfalls), moving out and linking, subfolder rule files, rules files, writing style for the AI, anti-patterns.
- [agent-compatibility.md](agent-compatibility.md) – Which ten questions to investigate afresh per coding agent during setup (rule files, subfolders, rules, subagents, skills, commands, MCP configuration, hooks, no-questions modes, headless), how to investigate, setup that does not survive a clone and must be made self-healing, rules for multiple agents, dated orientation snapshot.
- [knowledge-storage.md](knowledge-storage.md) – Ways of feeding knowledge, what belongs in a knowledge store and what does not, the LLM wiki with librarian (structure, context scoping, curation), alternatives (subfolder AGENTS.md, docs folder, rules, skills) with decision aid.
- [evaluators.md](evaluators.md) – Generator→evaluator pattern (subagent + acceptance duty), what the caller provides, limits and deception, multiple and specialized evaluators (security, performance, clean code, guidelines, architecture) with order and template, further subagent types.
- [skills-and-commands.md](skills-and-commands.md) – Skills vs. custom slash commands, loading levels, the description as trigger, what may go into the skill folder, guideline skills and skill pipelines, self-improving skills, provenance check, best practices.
- [mcp-and-tools.md](mcp-and-tools.md) – What MCP is and costs, decision rule MCP server vs. CLI/script, "providing is not using", enablement per application type (Playwright, cua-computer-use, read-only mailbox, further servers), pitfalls.
- [scripts.md](scripts.md) – Why scripts, the guiding image "a function call to a human", the ten binding principles for harness scripts, AGENTS.md entry after building, typical harness scripts, shipped and generated scripts are drafts to be tested, pitfalls.
- [autonomous-runs.md](autonomous-runs.md) – Building blocks, permission modes (dontAsk), sandbox, launch sequence (goal hierarchy, checklist, question round before goal), goal/loop, usage tracking, self-monitoring via cron, boundaries and abort conditions, steering without disturbing, named start/attach scripts per agent and OS when freilauf is not used (purpose, difference to freilauf, generated scripts are drafts to be tested for real), `tools/agent-start.py`.
- [workflow.md](workflow.md) – Standard workflow for AGENTS.md, planning levels 1–3 and the counterpole goal + check criterion, testing in the workflow, phrasing assignments (letter instead of prompt, XML delimiting, control questions), follow-up-question policy, dynamic workflows and evaluator chains.
- [freilauf.md](freilauf.md) – The superstructure to the built harness: schedules, worktrees, monitoring from outside, budget gates, merge, reports, notifications; where to read its current state and how to install it (Linux only, via its `SETUP_WITH_AGENT.md`); when it pays off and how it interplays with the harness; dated procedure for registering a project, the worktree-extras field for nested checkouts, and the traps around max_parallel and hub pushing.
