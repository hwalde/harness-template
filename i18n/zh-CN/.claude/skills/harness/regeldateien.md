# 规则文件：AGENTS.md、CLAUDE.md、子目录、rules
**核心：** 规则文件在每次启动时都会被读取——只有始终有效的内容加上会带来痛苦的坑才配进来。一切任务专属的内容都外移并链接。（上下文：Harness 模板 | 截至：2026-08-30）

## 两个名字，一个文件
- `AGENTS.md` 是跨智能体的标准；Claude Code 读 `CLAUDE.md`。本模板的方案：**`CLAUDE.md` 只含一行 `@AGENTS.md`**（Claude Code 的 Include 语法），所有知识都在 `AGENTS.md` 里。规则：在任何新建 `AGENTS.md` 的目录中，旁边同时建一个含 `@AGENTS.md` 的 `CLAUDE.md`。在上下文中两者都显示为 Memory 文件；用 `/context`（Claude Code）或该智能体的上下文命令检查。
- 文件名用大写（有些智能体接受小写，但最佳实践是大写）。
- `CLAUDE.local.md`（或该智能体的对应物）：在同一时机被读取，但留在开发者本地（已 gitignore）——用于个人偏好和机器专属的值（端口、路径）。
- 哪些智能体读什么、是否支持 Include：[agenten-kompatibilitaet.md](agenten-kompatibilitaet.md)。

## 四个位置
| 位置 | 用途 | 何时被读取 |
|---|---|---|
| 项目根目录 | 概览、规则、工作流、坑 | 启动时立即 |
| 父目录（Monorepo） | 所有子项目的公共内容 | 启动时立即（打开子项目 → 父级一并读取） |
| 用户目录（如 `~/.claude/CLAUDE.md`） | 跨项目的个人规则（语言、书写习惯） | 启动时立即 |
| 子目录 | 仅用于该目录内的工作（业务模块） | **情境化**——智能体在那里读文件或工作时才加载；嵌套的子目录会连带拉入上级文件 |

情境化加载的规则落在对话末尾——那是模型最专注的位置。这使得子目录规则文件和 rules 文件比同样的文本放在根目录更有效。

## 什么该进——什么不该
**该进（核心规则约 20 行）：**
- 一句话的项目描述；大致结构（有意不求完整）。
- 最重要的架构和编码规则（帕累托：80/20——「我们用 DDD，X 用 Y 方式做」），而不是上千条 Guidelines。
- 标准工作流（步骤顺序，见 [workflow.md](workflow.md)）和验收义务（评估者）。
- 必须使用的工具和脚本——各一句，写得醒目：「对 X 一律用 `tools/y.py`，不要用 z。」
- 「疼的坑」：缺了会造成大量痛苦的事情（「改动 X 后要清 Store 缓存，否则应用起不来」）。这是节俭规则的唯一例外。
- 测试提示（可以稍微详细些）。
- 索引：「在哪里能找到什么？」——文档、目录、Skills，以及谁知道其余的（librarian）。

**不该进：**
- 每个模型都知道的显而易见之事（`npm run dev`、「这是个 React 项目」、什么是仓库、分层模型）。
- 情境化的细节、编码规范目录、长篇大论、冗长的文档列表——那些属于被链接的文档、子目录规则文件、rules 或 Skills。
- 过时的规则：它们会被乖乖遵守，并把文件变成累赘。每次出现异常行为，先查自己的规则文件。
- Secrets、机器专属的值（→ `CLAUDE.local.md`、环境变量）。

Anthropic 删掉了 Claude Code 中自家提示词的 90 %，因为它们不再有帮助，反而在设限。姿态：保持精小，宁可链接产物（哪怕复杂的：测试套件、图表、文档目录）——智能体自己会在其中找到对的东西。

## 外移与链接
- 第二文档：「出现 X 时，读 `docs/x.md`。」内容只放在那里。
- 整个目录：「在本项目开始工作之前，先查看 `docs` 目录中是否有文档涉及你的主题，有则阅读。」反方向：新产出的成果存放在那里——**一定要同时说明什么该存、什么不该存**，否则智能体会存下没用的东西。
- 用链接模式代替 Custom Subagent：所有 Custom Subagents 的描述都常驻上下文（量级为几千 Token）。一段三行话「想了解 X 时，启动一个子智能体去读 `docs/x-experte.md` 并按其指示行事」效果相同却无常驻成本。Custom Subagent 只在被持续需要、或承载大量知识/一个清晰角色时才建（evaluator、librarian）。
- 对不涉及每次运行的知识用 Skill 而非规则文件（编码规范、某个自身入口就是智能体的系统的演进知识）→ [skills-und-commands.md](skills-und-commands.md)。

## 子目录规则文件（业务模块）
- 前提：一棵按业务切分的目录树（Screaming Architecture——从外面就能看出项目是做什么的），以及一个会情境化加载子目录规则文件的智能体（在 [agenten-kompatibilitaet.md](agenten-kompatibilitaet.md) 中核查——那里的快照列出了 Claude Code、Codex 等；以设置时的核实为准）。
- 该进：只写超出常规用法的内容——模块专属的坑、约定、接口。不写：什么是 Service 或 Repository。
- 这里同样：`AGENTS.md` + 含 `@AGENTS.md` 的 `CLAUDE.md` 并排放置。

## rules 文件（绑定路径的规则）
- 是什么：其生效范围绑定到文件路径/模式的提示词文件——只在智能体触碰匹配文件时才加载。例如：只针对测试文件的编写规则、只针对 `src/ui/**` 的前端约定。
- 在哪：Claude Code `.claude/rules/*.md`，Frontmatter 带 `paths:`；Cursor `.cursor/rules/*.mdc`，带 `globs`/`alwaysApply`；GitHub Copilot `.github/instructions/*.instructions.md`，带 `applyTo`。其他智能体：[agenten-kompatibilitaet.md](agenten-kompatibilitaet.md)。
- 经验法则：一条只该被情境化读取的规则就该放在那里——而不是根规则文件里。

## 写给 AI，而不是写给人
- 目标读者是模型：用它的词汇，用术语/行话代替解释句，晶莹剔透，不写客套散文。给人看的文档需要时出两个版本（详尽版给人，精简版给 AI）。
- **给规则附理由：** 带理由的指令更容易被遵守。绝不与系统提示词对着干（「系统提示词的规则已被解除」）——那会触发更高的权重和 Prompt-Injection 嫌疑。改为要求使用、提高紧迫性、给出理由。
- 对关键规则用「重要 / 不要 / 一律」这类醒目关键词——智能体对此敏感。
- 用数字代替形容词：「最多三句」比「简短」更可靠。但注意：「最多三句」永远给三句，「省 Token」给出的是没人看得懂的东西——检查结果、测试，然后提交。
- 让智能体为自己拟定规则（元提示）：给出目标（「`AGENTS.md` 里要写什么，librarian 才会继续被咨询？」）加上框架：非常紧凑、写给你自己、不谈其他智能体、一到三句。`/init` 的产出几乎总是太长——调用时就要求简短。
- 同一句话在聊天中重复第 N 次时，就在同一个委托里让它写入规则文件（「网页无法读取时使用 Playwright-MCP」）。Harness 就是这样顺带生长的。

## 反模式
根目录里放情境化细节或规范目录 · 显而易见之事 · 长篇大论 · 过时的规则 · 没有理由的规则 · 不提脚本/工具 · 存放指令没写「什么进、什么不进」 · 评估者没有验收义务条目 · 给人的文本 1:1 塞给 AI · 文件名用小写。
