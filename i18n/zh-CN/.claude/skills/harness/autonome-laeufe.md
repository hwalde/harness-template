# 自主运行：无追问、无停顿、无人值守
**核心：** 一次自主运行会栽在每一个无人应答的追问上、每一次登出即死的会话上、每一个悄悄把它掐断的限额上。Harness 把这三者全部消除。（上下文：Harness 模板 | 截至：2026-08-30）

## 组件概览
| 组件 | 用途 | 在模板中的位置 |
|---|---|---|
| 免追问权限模式 | 智能体从不为提问停下 | `tools/agent-start.py` 知道各智能体的模式 |
| 终端多路复用器（tmux / Windows 下 psmux） | 运行挺过登出；可以附着上去围观 | `tools/agent-start.py start/attach/send` |
| 提示词中的目标层级 + 可勾选的验收清单 | 智能体知道什么优先、何时算完 | [workflow.md](workflow.md)，下文 |
| 不让它在工作完成前停下的东西 | `/goal` 命令（Claude Code）或一个 Loop | 下文 |
| Usage 追踪 | 在配额限额前停下而不是死掉 | Usage 脚本，见下文 |
| 自我监控 | 发现挂起的脚本和迷路的智能体 | 智能体的 Cron/Loop + 检查脚本 |
| 评估者 | 验收由第二者检验 | [evaluatoren.md](evaluatoren.md) |
| 沙箱 | 安全来自环境的边界，不来自禁令清单 | 下文 |
| 时间计划与外部监控的上层建筑 | 当运行要定期无人值守时 | [freilauf.md](freilauf.md) |

## 权限模式（以 Claude Code 为例；其他智能体的对应物见 [agenten-kompatibilitaet.md](agenten-kompatibilitaet.md)）
| 模式 | 行为 |
|---|---|
| 手动 | 事无巨细都要问，连写文件都不许 |
| acceptEdits | 在项目目录内写文件不问；命令要问，除非已被放行（永久允许的命令它会记住） |
| plan | 只做规划，聚焦一份技术方案 |
| auto | 凡确信命令安全就执行；不确定时（例如带变量的删除命令）会问 |
| bypassPermissions | Shell 命令不问；少数事情（自己的配置文件）仍会问。企业里不受欢迎——`auto` 通常同样够用 |
| **dontAsk** | **通往自主的钥匙：** 从不提问；未被允许的会被静默拒绝并告知模型，模型另寻他路。封锁所有交互式追问工具（包括 `AskUserQuestion`）。子智能体本来就这样运行。需要在设置里配一份允许命令的 Allow 列表，否则它会拒绝得太多。 |

替代方案：`acceptEdits` 加预先放行的命令。对其他任何智能体都要找对应物——没有一个让它*没法*再提问的模式，它就不算真正自主地运行。

## 安全：沙箱而非削权
谁让一个智能体连跑数日，就既不希望它卡住，也不希望它连自己的 Skills 都不许编辑。这与「尽量少授权」相悖。正确的概念是：**全部放行，但放进沙箱**（例如面向编程智能体的 Docker 沙箱那样的 Micro-VM，或网络受限的容器/Worktree）。边界之内智能体百无禁忌；安全来自环境的边界，而不来自禁令清单的长度。没有沙箱就是在玩火——那至少也要 Worktree、Git 作安全网、不给生产访问权限。

## 启动流程（行之有效的顺序）
1. **写提示词**——短、手写、精确。内容核心是一份**目标层级**：目标 1、目标 2，外加一句明确的顺序说明（「目标 1 达成后，继续目标 2」）。目标的表述要让它可以死磕，但确实可达。
2. **删掉**智能体本来就会做、或对本次运行无关紧要的内容（「保持文档更新」、「记录 Learnings」——那些在 Harness 里）。剩下的是内核：目标、边界条件（Usage、费用）、被赋予的能力。
3. **给能力，不给执行计划：**「使用子智能体」留下；「每个错误启动一个」删掉。对做法的规定只有当背后有自己的观察时才正当（例如「先完整跑一遍，再集中修收集到的错误」，因为重启曾实测烧钱）。界线就在规定沦为看管之处。
4. **保持元层级清晰：** 若项目本身就用智能体工作，就存在*项目里的*智能体和*编程智能体的*智能体——提示词中的用词要保持无歧义。这类运行选更聪明的模型。
5. **让它排版**，在一个空聊天里：「把这段文本排版为 Markdown，不要改写任何内容」——文本用 XML 标签框起来，使数据与指令分离。
6. **让它生成验收清单：**「把需求写成可勾选的形式，按目标 1 和目标 2 分组。」逐句检查每个表述有无第二种读法（「强制性的依赖」≠「强制要使用」）——运行中没人再来追问了。
7. **用脚本在命名会话中启动：**`python3 tools/agent-start.py start --prompt-file lauf.md --name nachtlauf`。有多个脚本时，给新实例的第一个任务：调用各脚本的帮助并理解它们。
8. **先提问轮，后 Goal：**「在接下来的十分钟内提出相关问题；之后全自主工作。」作答。**在那之后**才设 Goal——一个已激活的 Goal 会阻止智能体为追问停下。提问工具要指名道姓（要求或禁止）。
9. **设 Goal：** 摘要 + 清单 + 工作方式（「全自主、不提问、不等待回答」）。粗查 Token 长度；命令在目标窗口里现敲（复制来的命令爱多出一个空格）。
10. **放手。** 关掉窗口，会话继续跑。别老往里看——围观才是难的那部分。

## 工作未完不得停
- Claude Code：`/goal`——条件写成可勾选的形式；条件未满足智能体不会中止（但它也不会无限跑下去）。
- 或者一个 Loop，用同一任务反复重启智能体，直到某个检查脚本报告「完成」（当心：没有中止判据、没有 Usage 检查的 Loop 是危险的）。
- 大目标：在正常聊天里详细描述，Goal 里只放要满足的条件。

## Usage 追踪（仅订阅配额下相关）
- 一个会话窗口（如 5 小时）加上周限额和模型限额。到 100 % 时运行实际上就死了：子智能体死掉或挂起；唯一出路是追加昂贵的额外配额。
- 解法：一个 **Usage 脚本**，返回百分比和重置时间点（数据来源因智能体而异——Claude Code 例如配置目录里的 Statusline/Quota 数据；否则用该智能体的配额命令或 Provider-API）。输出人类可读，另为 Wrapper 加一行字节稳定的结束行。
- 提示词中的指令：使用该脚本；数值越接近 90 % 检查间隔越短；超过 90 % 等到重置；**子智能体暂停并用同一脚本自查 Usage**——不知道限额的子智能体会不受约束地消耗主智能体的预算。
- **费用另行追踪**（API 费用 ≠ 配额）。

## 自我监控
- 长时间运行的脚本有时会挂；智能体会迷路。没人坐在屏幕前时，需要有个「人」时不时看一眼。
- 智能体自己给自己布置监控：Claude Code 用 `CronCreate` 工具或 `/loop`（「用你的 CronCreate 工具建一个每 30 分钟执行 `tools/watch.py` 的任务」）。工具要指名道姓，免得 Cron 工具变成 Chrome 工具；先用一个琐碎任务（每分钟「Hallo Welt」）测试，之后把测试任务删掉。
- 该任务检查什么：进程还活着吗、有进展吗、磁盘要满了吗、有脚本挂住吗、有子智能体停在没结果的地方吗。有发现：介入或重新拉起运行。
- 外部监控（包括智能体自己已无法上报的 Rate-Limits）和时间计划：[freilauf.md](freilauf.md)。

## 面对意外的行为准则：边界与中止条件
模型想达成目标，会走最短的路——通常这正是内建的刹车，但在目标压力下（「跳出框框想」）也是不受欢迎路径的根源。所以放手自主运行的人，要一并交代面对意外情况的行为：
- **硬边界：**「只迁移 Controller，其他一概不动。」「`src/api/` 之外不做任何更改。」「不发邮件、不部署、不碰生产系统。」否则智能体会把半个系统重写掉，因为「那就还得改这个和那个」。
- **中止条件：**「若你发现必须在 X 之外做改动，停下来，写明缺什么。」
- **时间允许时：** 头几个案例一起做，接下来它自己做，顺利则全部交给它。
- **理顺测试但不掩盖 Bug：**「把因代码改动而挂掉的测试理顺；若在此过程中发现 Bug，不要掩盖，写下来。」没有这句补充，测试会变绿、错误会消失。
- 粗粒度目标有毛边：「调试流水线」需要补一句「把修好的 Bug 从 Bug 清单里移除」，否则清单无限膨胀。
- Loop（用同一任务重启智能体）只在有中止判据和 Usage 检查时使用。

## 调控而不打扰
- 直接敲进聊天的提示会改变上下文并作用于后续一切——这是有意的调控（Steering）。而运行中途来一句「现在去用 librarian」毫无意义；在自主运行中，被提供的工具的使用频率低于预期。
- 静默诊断：把完整对话记录加一个问题交给第二个模型（Claude Code：`/by the way`），就能回答「它进行到哪了？」而智能体毫无察觉。模式：静默诊断 → 在运行之外解决问题 → 只把那一条必要信息投进聊天。
- 主智能体陷进细节工作时：「这件事最好启动一个子智能体，免得你分心。」长运行开局就说：「你只做编排；子智能体负责实现——这样保护你的上下文窗口。」
- 模型和推理力度不是一次性设置：无须思考的中间任务用更小的模型、更低的力度；要理解元层级和工具的运行，用最聪明的模型。

## 自我改进（可选）
允许智能体用**相关的** Learnings 续写它汲取系统演进知识的那个 Skill。风险：它把 Skill 优化坏、把核心决策扔掉。对策：在 Skill 中把不可谈判的决策标注出来；「用相关的 Learnings」，不是「用全部」。剩下的是一份无法消除的控制让渡。

## 把验证移到最后
有些结果只有人能验收。这时值得把终验可靠地放到最后（例如一个带时间标记的评论功能，其反馈由智能体逐条针对性处理），而不是让它一路上每个小事都截图送检——持续的中途检验很贵，Edge Cases 留给最后的人来看更好。

## `tools/agent-start.py` 速览
`doctor`（有哪些智能体/多路复用器可用）· `start --prompt/--prompt-file [--agent] [--name] [--dir] [--model] [--headless] [--attach] [--dry-run]` · `list` · `attach NAME` · `send NAME "Text"` · `kill NAME`。有多路复用器时产生交互式会话 `hx-<name>`；没有（或带 `--headless`）时智能体在后台运行，日志在 `.harness/runs/` 下。各智能体的 Flags 写在脚本开头的一张表里——Flag 变动时唯一需要改的地方。
