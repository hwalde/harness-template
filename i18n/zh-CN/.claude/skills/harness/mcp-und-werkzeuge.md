# MCP 服务器与工具：何时用 MCP、何时不用
**核心：** MCP 服务器给智能体提供工具（浏览器、桌面、外部系统）；它们消耗上下文，并以你的权限运行。MCP 服务器的竞争对手是脚本。（上下文：Harness 模板 | 截至：2026-08-30）

## MCP 是什么（三句话）
- Model Context Protocol：客户端-服务器协议（不是 REST）。编程智能体是客户端，服务器是一个把函数以「Tools」形式提供的运行中程序。
- 启动时智能体读取自己的配置、建立连接、收集工具列表并把它接到自己的工具之后。当模型调用一个 MCP 工具时，智能体把调用转交给服务器；结果以文本返回。
- 配置 = 命令 + 参数 + 环境变量，位于用户层或项目层（文件名因智能体而异，见 [agenten-kompatibilitaet.md](agenten-kompatibilitaet.md)）。MCP 服务器**不能**放进 Skill；可经插件分发。

## 它们的代价
| 成本类型 | 事实 |
|---|---|
| 上下文窗口 | 没有懒加载时，所有工具描述在**每次**请求时都被一并发送：五个服务器 ≈ 50k Token，带浏览器服务器很快到 100k。Claude Code 如今懒加载工具描述（Tool-Search）：每个实际用到的工具 ≈ 90 Token，外加每个服务器 ≈ 3 行。其他智能体（如 GitHub Copilot）则持续发送（Computer-Use 服务器 ≈ 12k，Playwright ≈ 4k）。用 `/context` 或该智能体的上下文命令检查。 |
| 未使用的服务器 | 每次请求照样花钱 → 把当前不用的平台的服务器关掉。 |
| 内存 | 标准构造：每个智能体实例一个服务器实例。开着许多智能体 = 大量 RAM；极端案例一个服务器 12 GB。 |
| 安全 | MCP 服务器**以你的权限**运行，且几乎无法审查（完整的应用程序，每次更新又从头再来）。一个把源代码上传到网络的服务器不会被任何杀毒软件识别。来源不明 → 不安装。Secrets 有时落在 MCP 配置里——绝不提交进仓库。 |
| 批量安装 | 目录站列出成千上万的服务器。每多一个服务器（如同每多一个 Skill、每多一个子智能体）都会降低模型表现并抬高成本。装的是项目需要的——不「囤货」。 |

## 决策规则：MCP 服务器还是 CLI/脚本？
每次扩展前的前置问题：**这个任务可以算法化判定吗？**可以就用脚本（确定性，出错是可修的 Bug）。需要专业判断或权衡的留给模型。之后才是 MCP 还是 CLI 的问题：

| 判据 | → MCP 服务器 | → CLI 工具 / 脚本 |
|---|---|---|
| 状态 | 有状态：打开的浏览器标签页、会话、随服务器存活的窗口 | 无状态：「服务器在跑吗、端口空闲吗、日志里有什么」，小型可复用算法 |
| 远程 | 功能运行在另一台机器上；自己的应用要能被外部使用 | 直接调 REST-API，或基于 API 写个脚本 |
| 使用频率 | 持续需要（每天要操控浏览器） | 情境性需要 |
| 可见性 | 工具要无处不在地出现在模型视野里 | `AGENTS.md` 中恰当位置的一句话就够 |
| 已有 CLI | – | 若已有命令行工具（`gh`、厂商 CLI、`kubectl`、`aws`、`psql`……），MCP 服务器就是多余的——智能体对这些工具的熟悉程度常胜过开发者 |
| 可审查性 | 几乎不可审查，权限全开 | 可读、可审查、在仓库中受版本管理 |
| 模型强度 | 小型/本地模型会忘掉脚本 → MCP | 强模型记得住一个提示 |
| 打包 | 仅用户/项目层，进不了 Skill；Secrets 在配置里 | 脚本躺在仓库或 Skill 目录里 |

经验法则：**状态、远程或每日使用 → MCP。其余一切 → 脚本**（[skripte.md](skripte.md)）。一个复刻现成 CLI 命令的 MCP 服务器是个错误。

## 提供不等于使用
装好的工具不会自动被使用。要让它被使用，就在 `AGENTS.md` 里写明：「对 X 一律使用工具 Y」——必要时配上反面「不要用 Z」。示例：「网页无法读取（Fetch 被拦）时，用 Playwright-MCP 来读。」·「允许用 Computer Use 调试桌面应用。」

## 按应用类型推荐的赋能
赋能的目标：智能体自己获取信息、自己测试、自己查看——每一轮「人点一遍然后写个提示词说哪里不行」都在烧时间。

| 应用 | 推荐 |
|---|---|
| 命令行 / 库 | 不需要浏览器/桌面操控；测试和脚本就够 |
| Web 应用 | **Playwright-MCP**（或 Selenium/Puppeteer 等价物）：打开页面、逐个点击、填表单、截图、读浏览器控制台和网络。服务器上用 headless。形态：独立的空浏览器（无登录，安全）· 真实浏览器中的标签页组（有登录，访问面大——要权衡）· 混合并锁定部分页面。**不能替代测试**——它服务于工作中的试用和查看；最后要跑 E2E 测试。 |
| 桌面应用 | **cua-computer-use**（开源 Computer-Use-MCP）：桌面应用的同类方案，应用可在后台运行。只有当 `AGENTS.md` 明确允许时，智能体才会把它当调试工具用。 |
| 布局/设计工作 | 多模态模型本来就能看截图；视觉服务器（位置、间距）只在有具体需求时 |
| 生成图像 | 图像生成服务器只在项目需要图像时 |
| E-Mail | 只**读**（List/Read，无发送功能）——例如核对确认邮件/Newsletter 注册。红线：无人工批准不发送。 |
| 工单/Wiki/流水线系统（Jira、Confluence、CI） | 先查有没有 CLI；Confluence 内容是写给人的，常常是垃圾场——一个适配智能体的 Wiki（[wissensablage.md](wissensablage.md)）通常是更好的来源 |

## 配置位置（简版）
项目本地配置，让每个克隆都有同样的工具；Secrets 走环境变量，绝不进仓库。各智能体的文件名见 [agenten-kompatibilitaet.md](agenten-kompatibilitaet.md)。添加前后都检查上下文消耗。

## 坑
- 只因为目录站里有就装 MCP 服务器——没有 Use Case。先有 Use Case，再有服务器。
- 装了 GitHub/GitLab-MCP，尽管 `gh`/`glab` 就在那里。
- 厂商 CLI 会不问自取地带上 MCP 服务器 → 检查上下文视图。
- 把浏览器操控误当测试替代品。
- 真实浏览器中的标签页组：智能体此后绝不许关闭浏览器或碰别人的标签页——若选择该形态，这必须作为规则写进 `AGENTS.md`。
- 没有明确许可时，Computer Use 不会被当作调试工具使用。
