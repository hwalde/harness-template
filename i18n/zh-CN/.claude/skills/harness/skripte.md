# 为编程智能体服务的脚本
**核心：** 一切可算法化判定的事情都属于脚本；AI 做决定，脚本来执行。本 Harness 的每个脚本都按下面的十条原则构建——无须再问，它们在这里始终有效。（上下文：Harness 模板 | 截至：2026-08-30）

## 为什么要脚本
- **确定性：** 脚本每天给出同样的结果；出错是一个可以修的 Bug。模型的回答今天这样、明天那样。示例：静态代码分析用脚本，而不是「你看看这些文件」。
- **分工：** AI 决定*该发生什么*、*在哪里*；脚本去做。凡不需要 AI 就能脚本化的，都脚本化。
- **减负：** 一个检查服务器是否在跑、端口是否空闲、Health 端点是否报错、日志里有什么的脚本，是经典的 Harness 组件。优化过的脚本让智能体更强。
- **边界：** 专业权衡（「这个切分合理吗？」）留给模型。另外：已有现成工具之处（浏览器操控、Computer Use、`gh`），不要再造脚本。
- **公示：** 模型「闻」不到脚本。它必须被提及——在 `AGENTS.md`（一句话）、在聊天中或在某个 Skill 里。脚本 vs. MCP：[mcp-und-werkzeuge.md](mcp-und-werkzeuge.md)。

## 指导思想：CLI 工具是对一个人的函数调用
调用者是一个 LLM——把它当作聪明的同事对待：它认识每个术语、不需要说教，但值得获得让无差错工作成为可能的整备。调用要简单到几乎不可能用错；输出要清晰到误解的几率趋近于零。内部由算法和数据结构工作；接口上说人话——双向都是。

## 十条原则（对本 Harness 的所有脚本具有约束力）

### 1. 快速退出
脚本绝不许持续运行——智能体在等结果，否则会挂住。若需要后台进程（服务器），脚本以脱离方式 spawn 它（`start_new_session=True`，日志进文件）并立刻带着 PID 退出。

### 2. 自解释且简单
- 无参数调用 = 帮助，解释该工具怎么用。
  例外：只有唯一一个安全、幂等操作的脚本，可以在无参数调用时直接执行该操作，前提是输出说明发生了什么（`-h/--help` 仍然可用；示例：`tools/sync-agents.py`）。
- 参数尽可能少；参数说任务的语言，不说内部结构的语言（一段原文引用或一个时间戳，而不是索引或对象路径——内部 ID 智能体得先去弄，还会弄混）。
- `AGENTS.md` 里需要的文档越少越好：一行（`tools/check-logs.py – 日志文件的错误分析`），不是 15 行。

### 3. 渐进披露
最顶层：只有最重要的子命令。细节、选项和子帮助页在各自的层级上才出现。

### 4. 人类可读的输出——由消费者决定格式
顺序：Markdown > 连续文本 > XML > JSON（避免）。LLM 是读者，不是解析器；嵌套的 JSON 会撕碎上下文关联。例外：若消费者是脚本（流水线、做解析的 Wrapper），就给这个消费者它的格式——比如一行字节稳定的结束行或一个 `--json` Flag。格式选择**不**交给智能体；模型会误以为 JSON 合适。

### 5. 省 Token
全部输出都会落进上下文窗口。清晰优先于简短，但两者兼得时：又短又清晰。不要横幅、不要点线、不要重复。`服务器运行中（端口 8080，已运行 5 分钟）。无近期错误。` 而不是一份状态报告。

### 6. 导航而非数据倾倒
绝不一次给出全部。概览（最新错误在前、时间戳、每条一行）加上查看细节、翻页（`--page`）、过滤（`--errors`、`--search`）的命令。让智能体自己选择接下来想看什么。

### 7. 输出即提示词——也是第一道验证
输出的每一句话都会作为指令落进上下文。输出要起引导作用：导航提示、结合上下文的观察、**建议而非命令**（「错误 #1 距今 8 秒，很可能源自你的改动——建议：`tool.py logs --detail 1`」）。对改变状态的命令：确认发生了什么、展示其在上下文中的影响、给出已填好参数的撤销命令——智能体当场就能核验自己的操作。提供时间参照（条目的年龄），因为模型没有时间感，否则找不到自己刚写下的日志条目。

### 8. 替对方着想
- 多智能体安全：「服务器 8 秒前刚被启动——可能有其他智能体在并行工作。用 `--force` 强制执行。」
- 合理排序（最新在前）、前置检查（编译通过吗？端口被占了吗？被谁？）、在脚本里计数和测量，而不是在模型里。
- 把数据关联起来，而不是零散抛出（每个失败测试对应的浏览器日志、网络、服务器日志）。

### 9. 用现成的语言，不搞隔离
Python 优先（先检查是否可用；否则 Bash）。写成操作系统无关（`pathlib`、`shutil.which`，不用 Shell 特有玩法）。**不用虚拟环境**——只用标准库或不带 venv 的 `pip install`；启动时检测缺失的包并给出安装命令。

### 10. 错误信息是行动指令
症状 + 应然/实然 + 下一步：`中止：.env 中缺少 API_TOKEN（期望：API_TOKEN=<token>）。填入后重新调用。模板：.env.example`——不给无解读的堆栈跟踪。面对含糊的错误，智能体会重试调用或瞎猜；一条带修复方案的信息能把失败尝试变成一步到位的修复。

## 建成之后：写入 `AGENTS.md`
不被提及的脚本对智能体而言不存在。条目包含：名称与调用方式、何时使用、它取代什么（哪个旧命令不再使用）。措辞要醒目——「重要/不要/一律」这类关键词能引起智能体注意；短句；只写主命令，子命令由智能体调用时自行发现。

```markdown
## 启动/停止服务器
重要：不要直接用 `npm start` 启动服务器。一律使用 `python3 tools/server.py start`
——它会先编译、检查端口冲突、防止重复启动。
- `python3 tools/server.py` – 显示各命令（start、status、logs）
```

## 典型的 Harness 脚本
| 脚本 | 用途 |
|---|---|
| `tools/agent-start.py`（模板内置） | 免追问启动编程智能体，可选进 tmux/psmux；`list`、`attach`、`send`、`kill`、`doctor` → [autonome-laeufe.md](autonome-laeufe.md) |
| `tools/sync-agents.py`（模板内置） | 把 `.claude/agents/` 中的子智能体定义转换为其他智能体的格式 → [agenten-kompatibilitaet.md](agenten-kompatibilitaet.md) |
| 服务器/服务操控 | 带前置检查的启动、状态、带导航的日志、重启保护 |
| 日志分析 | 最新错误在前、年龄、过滤、查看堆栈跟踪的 Detail 命令 |
| 测试运行器包装 | E2E 并行、失败项顺序重跑、每个测试关联浏览器/网络/服务器日志 |
| Usage 脚本 | 配额百分比 + 重置时间点，让自主运行在限额前停下 → [autonome-laeufe.md](autonome-laeufe.md) |
| 监控 | 检查挂起的脚本和迷路的智能体；由智能体经 Cron/Loop 周期性调用 |
| 计数/测量工具 | 词数、长度、尺寸——模型不擅长数数 |
| 构建/发布 | 发布构建只有一个脚本，在 `AGENTS.md` 中定为唯一途径 |

## 坑
- 脚本存在，但没在任何地方被提及。
- 输出整份日志文件的 Wrapper（臃肿）；JSON 块输出；把智能体堵住的长时间运行者。
- 脚本输出是提示词——因此也是攻击面：输出中的外来内容（邮件、网页、工单）要清晰标记为数据（例如 XML 标签），绝不格式化成指令。
- 小型/本地模型更容易忘掉脚本——那里要更明确的提示，或用 MCP。
